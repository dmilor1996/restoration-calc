# Моя мастерская

Личный Android-инструмент мастера-реставратора. В том же репозитории живёт опубликованный веб-калькулятор. Перед задачей прочитайте PROJECT_STATUS.md и относящиеся к запросу разделы docs/REQUIREMENTS.md. Архитектура описана в docs/ARCHITECTURE.md, интерфейс в docs/DESIGN.md, восстановление среды в docs/DEVELOPMENT.md.

## Начало сессии

В PowerShell откройте рабочую копию, обычно C:\Projects\restoration-calc. Выполните:

```powershell
git status --short --branch
git fetch origin
git branch -avv
git log -8 --oneline --decorate
.\dev.ps1 doctor
```

Сверяйте локальные коммиты и PR, особенно если появились новые ветки. При чистом дереве начинайте задачу командой `git switch -c work/краткое-название` от проверенной версии. Если в дереве есть работа пользователя, используйте отдельный каталог через `git worktree add -b work/название ../workshop-задача HEAD`. Основную ветку обновляют после проверки и приёмки. Для отката опубликованного коммита используйте git revert.

## Где менять код

| Задача | Исходники |
| --- | --- |
| Экраны APK | android-app/mobile/ui, mobile/workshop.css |
| Обработка команд, время, деньги | android-app/mobile/work/model.js |
| Транзакции и резервные копии | android-app/mobile/work/store.js, backup.js, files.js |
| Формулы для сайта и приложения | js/calc.js и tests/calc.test.mjs |
| Подробный калькулятор и совместимость | Корневые js/, css/, index.html и android-app/mobile/calculator.html |
| Упаковка и Android | android-app/scripts/copy-web.mjs, capacitor.config.json, android/ |
| Приёмка | android-app/tests, android-app/scripts, tools/workshop.py |

Редактируйте исходники. `www/` и Android assets создаёт сборка. Сохраняйте applicationId, origin WebView, формат старых расчётов и читаемость существующих записей. Суммы и площадь сверяйте по единицам конкретной модели. Изменения IndexedDB и формул сопровождайте тестом старой записи или контрольным расчётом. Названия, доступные роли и стабильные data-testid предпочтительны для проверок формы.

## Перед передачей результата

1. Для быстрой итерации запустите `.\dev.ps1 test`. После изменения экрана проверьте его и в упакованном APK.
2. `.\dev.ps1 verify` запускает полный Windows-цикл. Проверьте report.json, снимок и XML последнего запуска в artifacts/runs. Для Android Back, системного списка и авиарежима есть дополнительная проверка `.\dev.ps1 native`.
3. Сопоставьте проверенные сценарии с запросом, отдельно укажите пропуски. Обновите PROJECT_STATUS.md и CHANGELOG.md при существенном изменении.
4. Проверьте `git diff --check` и содержимое индекса. Коммитьте только файлы задачи. Ключи подписи, .env, клиентские данные, дампы, отчёты и APK хранятся вне Git. Избегайте force-push, сброса чужих изменений и очистки данных устройств.
5. Эмулятор для автоматизации — Workshop_QA_API34. Физический телефон и пользовательский AVD имеют отдельные данные. Выпуск для обновления телефона проходит существующий процесс подписи и приёмки.

Команды не зависят от агента: их можно запускать в обычном терминале, Desktop Commander или Codex.
