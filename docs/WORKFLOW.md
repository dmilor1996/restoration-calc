# Совместная разработка через Chat / Work / GitHub
Версия: 0.1 · 19.11.2026

## Роли
**Chat — обсуждение.** Свободное описание идеи, фотографии, примеры рабочего дня, эксперименты по UX. Не считать каждую идею утверждённым требованием.
**Work — реализация.** Изучить актуальный код и docs/, уточнить только критические развилки, выполнить согласованную задачу, проверить и подготовить PR / APK.
**GitHub — источник актуальной технической правды.** Документы, код, тесты, история и ревью.
**Пользователь — приёмка.** Проверяет реальное поведение APK на телефоне, сообщает неудобства, принимает или отклоняет изменение.

## Цикл задачи
1. Короткий запрос: что хочу делать и зачем, пример из жизни.
2. Ассистент сверяет с docs/ и текущим кодом. Разделяет установленные факты, предложения, открытые вопросы.
3. Для значимой задачи — отдельная ветка; не переписывать main напрямую.
4. Изменение кода + тесты + описание, что поменялось и что осталось непроверенным.
5. Автосборка preview APK, ссылка на Actions/артефакт; при ошибке — лог и причина.
6. Приёмка на физическом устройстве. Исправления в той же ветке.
7. Только после приёмки — объединение в стабильную линию и подпись release.

## Правила изменения кода
- Не ломать веб-калькулятор при работе над мобильным UI.
- Не удалять, не массово перезаписывать и не мигрировать данные без проверенного backup.
- Не выдавать неисполненные тесты за пройденные.
- Не сохранять приватные ключи и секреты в публичном репозитории.
- Не ставить/не публиковать APK автоматически от имени пользователя.
- Использовать отдельные ID и идемпотентные операции для времени и списаний.
- При изменении бизнес-правил обновлять тесты и соответствующую документацию.

## Шаблон постановки задачи в Work
«Изучи docs/PRODUCT_VISION.md, docs/ARCHITECTURE.md, docs/ROADMAP.md и актуальный код ветки. Нужно: [описание обычными словами]. Не меняй опубликованный сайт. Реализуй в новой ветке, добавь тесты, запусти доступные проверки, создай PR. Сообщи, что смогу проверить на телефоне и что не проверено».

## Приоритеты при конфликте
1. Сохранность пользовательских данных.
2. Корректность учёта финансов/времени/склада.
3. Стабильность установленной версии.
4. Простота использования.
5. Визуальная выразительность и новые функции.

## Важное ограничение
Контекст обсуждений ChatGPT может передаваться не полностью. Утверждённые решения переносить в docs/ и PR-описания. Каждая Work-сессия начинает с повторного чтения актуального состояния репозитория.
