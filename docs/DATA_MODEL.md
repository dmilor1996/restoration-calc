# Концептуальная модель данных
Версия: 0.1 · 19.11.2026
Статус: проект, **не схема уже внедрённой базы**.

## Сущности
### Project / Объект
id, legacyOrderId (optional), clientId (optional), название, адрес, заметки, план работ, расчёт, статус, даты, snapshot финансовой оценки, ссылки на фото. Один объект может включать несколько рабочих сессий и выездов. Старый заказ в расчётной системе не удалять и не переписывать ради нового проекта.

### WorkSession / Рабочая сессия
id, projectId, дата/время создания, статус (planned / active / paused / completed / cancelled), события, поправки, версия схемы. Сессии могут повторяться на одном объекте. Дорога — отдельная работа/запись, не обязательно входит в таймер реставрации.

### SessionEvent / Событие
id, sessionId, type (start / stage_change / pause / resume / finish / correction), stageId, timestamp UTC, deviceId, clientMutationId, optional note. Запрещён повторный учёт одного clientMutationId. Таймлайн — производная от отсортированных событий; ручная правка оформляется как correction с причиной. Требуется определить правила при конфликте нескольких устройств и неверных системных часах.

### Stage / Этап
id, название, категория, признак учёта времени. Каталог редактируемый. Один и тот же этап может встречаться несколько раз в рамках сессии. Не хранить только одну общую продолжительность «шлифовки», иначе пропадёт история переключений.

### Tool / Инструмент
id, название, бренд/модель, категория, серийный номер (опционально), дата/цена приобретения, состояние, место хранения, комплект, фото (в будущем), заметки, история обслуживания и использований. Не путать инструмент с расходными материалами.

### Consumable / Материал
id, тип (лак/масло/морилка/абразив и др.), производитель/артикул, базовая единица (мл/г/шт), цена закупки, допустимая упаковка и единицы отображения, минимальный остаток, место хранения, примечания. Уникальность не основывать на названии, оттенке или упаковке: один материал может быть закуплен повторно.

### StockMovement / Движение запаса
id, consumableId, projectId (optional), sessionId (optional), type (receipt / usage / return / adjustment / writeoff), deltaQuantity в базовой единице, закупочная цена/стоимость при движении, дата, уникальный clientMutationId, note. Одна проводка = одна фактическая операция; повторный сетевой запрос не должен менять остатки дважды. Отрицательные остатки — предупреждение или политика запрета, не скрытый пересчёт.

### ToolUse / Использование инструмента
id, toolId, projectId, sessionId (optional), начало/конец либо отметка «использован», заметки. Дальнейшее техническое обслуживание может основываться на истории эксплуатации.

### FinancialActual / Фактические расходы и поступления
id, projectId, category, amountMinorUnits (целые), currency, occurredAt, source (manual / stock_usage / travel / service), sourceRefId (optional). Деньги за работу и расход материала не должны дважды попадать в прибыль. Налоги и накладные расходы учитываются отдельно, если заведены.

### Achievement / Достижение
id, ruleVersion, источник/вычислимое условие, дата, данные подтверждения. Большинство показателей (месячный доход, количество объектов, средний час) лучше рассчитывать по истории, а не вести вторую независимую таблицу.

## Связи
- Project 1 → N WorkSession, FinancialActual, StockMovement, фотографии.
- WorkSession 1 → N SessionEvent.
- Consumable 1 → N StockMovement.
- Tool 1 → N ToolUse.
- Пользователь 1 → N Project, Tool, Consumable и отдельные настройки.

## Общие технические поля
schemaVersion, id, createdAt, updatedAt, deletedAt (для обратимого удаления), ownerUid. Для локальных событий — deviceId, clientMutationId и очередь отправки. Контроль доступа всегда по ownerUid на уровне правил облака, а не только в интерфейсе.

## Сценарии, которые модель обязана пережить
- Начало работы офлайн → перезапуск приложения → продолжение → синхронизация.
- Повторное нажатие «Завершить» не создаёт вторую сессию и не списывает материал дважды.
- Прерывание приложения во время активной сессии.
- Возвращение к ранее завершённому этапу.
- Работа на объекте два и более дня.
- Исправление ошибочно записанного времени и расхода с сохранением истории.
- Покупка ещё одной упаковки лака по другой цене.
- Возврат неиспользованного материала со списанного объекта.
- Удаление и восстановление заказа без потери взаимосвязанных документов.
- Открытие существующего старого заказа после обновления схемы.

## Техническое правило
Нельзя внедрять облачную модель только по этому тексту: сперва тесты миграции, доступов и повторных операций, затем пробная сборка на Android и резервная копия.
